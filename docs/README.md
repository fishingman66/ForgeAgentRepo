## 阅读建议

1. 先读根 [README](../README.md) 建立功能全貌，再按业务域进入对应文档。
2. 每篇文档独立成文，交叉点用「见第 X 部分 / 见另一篇文档」指路；文档间以《书名号》与相对链接互引。
3. 各篇的「决策与取舍记录」是跨会话最有价值的部分——记录了方案态与实现的偏差、被否方案与依据、实测踩坑，二次开发前建议通读。

## 评测基线（baseline/）

`baseline/` 存放知识库检索的可复现评测资产，与方案文档分开维护：

| 文件 | 说明 |
| --- | --- |
| `baseline/kb-baseline-corpus/*.md` | 6 篇语料（部署 / 权限 / 知识库 / 工作流 / 排障 / 记忆） |
| `baseline/kb-baseline-cases.json` | 30 条用例：问题 + 对应文档 + 精确证据片段 |
| `baseline/kb-baseline-r0.md` / `.json` | R0 基线结果与逐用例明细：**HitRate@5 93.33% / MRR 0.8667 / NDCG@5 0.8841**（30 用例、6 篇语料、36 分块） |
| `baseline/kb_baseline.py` | 一键复现脚本（建库 → 灌语料 → 跑用例 → 写回结果 → 删库）；`--no-write` 只打印不覆盖 |

> 改语料或用例等于改基线：必须重跑并存档为新的版本号（r1、r2…），否则历史对比失效。
> **评测数字可复现的三个前提**（缺一个就漂）：同分排序破平（RRF 按 chunkId、全文 SQL 按 id、本地向量按 id）、夹具串行摄取、每轮 `OPTIMIZE TABLE agent_kb_chunk`（InnoDB 全文索引对已删行异步清理会改 IDF）。各期回归均以此基线为准，多轮实测不降。
