# 第一部分 · 第一轮增强（P0 运行可靠性 · P1 配置治理层 · P2 执行内核增强）

回答的问题是：**「智能体凭什么被放心发布、出问题怎么查、改了之后怎么知道没变差」**。参照 OpenAgentFlow（OAF）的机制设计，补齐最薄弱的治理层，不重做已领先的交互与业务资产层。三阶段形成闭环：**配置可追溯（版本快照）→ 发布有门禁（评测基线）→ 运行可下钻（全链路 Trace）→ 断线可续传（SSE 缓冲）→ 多 Agent 可并行 → 记忆可分层**。

总体策略：**移植机制设计，不复制实现代码**——两边底座差异（Spring Security↔Sa-Token、Flyway↔手工幂等增量、自研 client↔AgentScope、Kafka↔@Async）决定搬码不可行。

## 明确不做

1. 不引入 Kafka / Outbox / 多角色 Worker（单体 + `@Async` + SnailJob 足够）。
2. 不做 Prompt A/B 灰度分桶、解决方案模板广场（市场已有，重复建设）。
3. 不做 Helm / KEDA / 混沌工程 / 高并发基线（无对应部署规模）。
4. 不合并两套工作流引擎；不重写聊天页。
5. `typecheck` 不接入 build（历史欠账见路线图）；Playwright 不引入。

## 决策与取舍记录

| 决策点 | 结论 | 依据 |
| --- | --- | --- |
| 移植原则 | 拿 OAF 的表结构、判定逻辑、事件协议、交互抽象；不复制执行实现与演示态代码 | OAF 存在假并行（同步 for）、门禁默认放行、硬编码假弹层、测试近空等「宣传口径大于实现」问题 |
| 门禁默认收紧 | 未配置策略用内置阈值而非放行；豁免不跳过基础检查 | OAF 的默认放行是要避开的坑，方向反过来 |
| Trace 短事务 | `REQUIRES_NEW` 显式短事务，网络调用不持事务 | 业务回滚不丢诊断 |
| 授权方式 | 裁剪 toolDefs（不装配）而非运行时拦截 | 模型看不到被过滤工具，比事后抛异常干净，不改内核 |
| C1 用规则不用 LLM 分类 | 不增加每轮延迟与成本 | OAF 路由是相似度+正则而非 LLM，价值在结构化计划不在分类精度 |
| 评测会话隔离 | `temp=1` 标记不进正式列表 | 批量评测不刷屏 |
| 记忆增强边界 | P2 只做评分层，向量/图谱不做 | 「等有具体需求再拆」；后由记忆体系专项接管 |
| 前端质量基线 | 不装新依赖、typecheck 不接 build | 48 个历史类型错误强制接入会阻断构建 |

# 第二部分 · 工作流专项（第二轮）

本轮起点是「workflow 没法使用」——四类叠加根因（工具节点前后端参数字段错位、聊天侧不读 workflowJson、增量 SQL 硬依赖、一组体验缺陷），W0~W4 修根因、W5~W9 升级执行内核、W10 打通对话；随后是体检修复四批与资源域双模式。

「Agent 编排画布」是面向一次 LLM 任务的自研 JSON DAG 引擎，与 `forge-workflow`（warm-flow，OA 审批）零依赖并存，页面与文档中已做命名区分，不混用。

## 引擎能力现状

**12 类节点**：start / end / llm / tool / knowledge / http / code / condition / loop / parallel / join / approval；画布支持试运行（异步 + 逐节点 SSE 实时点亮）、版本快照与回滚、运行回放。

| 能力 | 现状 |
| --- | --- |
| 失败策略与重试 | 节点级 `failureStrategy`（terminate / continue+fallbackOutput / goto 跳转）、`retryCount`(0~3)、`retryIntervalMs`(≤5s)、`timeoutMs`（虚拟线程池 + cancel）；超时/取消节点禁止重试与 GOTO（防重复副作用）；重试按 attempt 记录在单条 NodeTrace 输出中 |
| 模板与条件 | `{{a.b[0].c}}` 点路径 + 数组下标深取（完整键优先、含点键兼容）；条件 8 运算符（长词优先、数字优先），不支持的表达式显式报错；条件出边按 `branchName` 关联（全无标注兼容旧数据下标对齐，混合标注为校验 blocker） |
| 并行与 JOIN | 出边即分支、BFS 求共同 JOIN（未汇聚/多汇聚报错）、有界池并发、分支内禁嵌套并行/审批/条件分支（双拦截）、按分支起点序归并（`putIfAbsent`）、JOIN 输出注册为 `<join名>.output` |
| 试运行 | 异步提交（先落 run 返回 runId）+ 逐节点 SSE（`RunEventBuffer` 续传）+ 画布真实顺序点亮；`dryRun`（外部节点桩输出，0 Token 验证图结构）、`startNodeKey`、图级 `maxSteps`（默认 100 上限 500）；同步端点保留 |
| 幂等 | `agent_workflow_run.idempotency_key` 唯一索引：Cron 键 = `cron:{triggerId}:{调度分钟}`、Webhook 按 `Idempotency-Key` 头、API 端点复用；命中终态 run 复用结果、命中 running 去重提示 |
| 审批 | 独立过期时间（默认 24h 上限 30 天）+ 每 5 分钟清扫；审批决策与清扫条件更新互斥（`WHERE status='pending'`）；审批中心带来源筛选与截止时间 |
| 对外 API | `POST /workflow-api/{endpointCode}`：空间 API 密钥鉴权（SHA-256）、端点级限流（Redis）、IP 预限流（鉴权前 120/min）、鉴权失败 10/min、256KB 闸门、超时 `cancel(true)`、错误消息模糊化；响应 `output` 64KB 截断 |
| 语义防护 | http 节点 SSRF 防护：scheme 白名单、DNS 解析后拒绝回环/私网/链路本地、禁重定向；开关默认 true。已知纵深缺口 DNS rebinding 记录在案 |
| 兜底 | 僵尸 running 每 5 分钟主动清扫（30 分钟阈值）；快照轨迹超 256KB 按 output 4000 字符截断（varsJson 不截断——它是恢复与插值的输入）；健康检查探 MySQL/Redis |

## 对话 × 工作流（触发模式）

`agent_info.workflow_trigger_mode`（0 关闭 / 1 每轮自动执行 / 2 按意图路由）：

- **auto**：命中即走工作流执行链，结果作为本轮回答；**manual**：问题命中工具或知识意图（复用 IntentRouter 规则版）时走工作流，否则 ReAct。
- 流式路径：异步提交后台执行，节点事件**按原事件名转发进聊天 SSE**，终态一次性补发完整 delta（聊天页零适配）；聊天页有「工作流执行轨迹」时间线（vitest 覆盖）。
- 失败语义：工作流失败**不降级 ReAct**（避免重复计费），失败原因作为助手回复落库，Trace 可下钻；`pending_approval` 返回审批提示，续跑在工作流侧完成。
- 消息 `extJson.runner="workflow"`，WORKFLOW 轨迹携带 wfRunId 可下钻运行记录。

## 资源域双模式（平台共享 / 空间私有）

工具、数据源、模型三类资源各自带 `workspace_id`：NULL = 平台共享（全空间可用，**仅超管可建改**——防凭据提权），非空 = 空间私有（本空间可见，DEVELOPER/ADMIN 可管）。两种模式并存，存量资源默认保持共享（上线零行为变更）。

- 统一守卫 `ResourceAccessGuard`（agent-core，纯静态可见性矩阵）：`assertReadable/assertWritable` + `applyVisibleCondition` 把 `(workspace_id IS NULL OR = ?)` 下推 SQL；全链路只认这一个口子（列表/详情/增删改/绑定/对话/工作流/问数/免登录/市场发布拦截）。
- 边界：归属一经创建不可变；禁止降级；私有资源引用禁止发布到市场；开关 `agent.resource-sharing.enabled=false` 可一键收紧全私有。
- 覆盖范围：工具/数据源/模型三域；**MCP 服务器仍为平台级**（未补归属）。

## 质量与加固现状

- **单测 52 用例**（forge-agent 模块）：表达式引擎 11 + 图校验器 21 + 资源域守卫 8 + 记忆预算/工作记忆 12；`WorkflowExpressionEngine` 与 `WorkflowGraphValidator` 已从约 2200 行服务类提取为无依赖纯静态类。
- 体检修复（三视角独立审计产出）：聊天入口越权（`checkWsMember` 收敛）、治理控制台空间校验、调度池扩容、RunStreamEmitter 虚拟线程 Pinning 消除、审批竞态条件更新、webhook 限流键加固、Actuator 收窄。
- 工作流执行体已于 2026-11-13 拆分为 `WorkflowNodeExecutors` / `WorkflowGraphEngine` / `WorkflowRunLauncher` / `WorkflowTraceCodec`，`AgentWorkflowServiceImpl` 降为 489 行门面（详见 [06-平台化改造方案](06-平台化改造方案.md) 第五节）；Redis key 前缀常量化未集中。

## 明确不做

1. 不合并两套工作流；不引 Kafka 异步任务中心；不做灰度分桶与 SUBFLOW 子流程。
2. 不改前端画布库（节点类型超 15 类再评估）；不学 OAF 的假动画，走真事件流。
3. MCP 服务器暂不补空间归属；`AgentWorkflowServiceImpl` 不为拆而拆。
4. G4 节点插件 SPI 搁置，触发条件为出现第一个内置节点表达不了的真实编排需求。

## 决策与取舍记录

| 决策点 | 结论 | 依据 |
| --- | --- | --- |
| 借 OAF 什么 | 执行语义（真并行 + BFS JOIN、失败策略三分支、dryRun、指定起跑、节点级超时、模板深取、幂等）；不搬实现 | 第一轮口径延续，本轮多借执行语义 |
| 避开 OAF 的坑 | 审批不闭环（本项目审批联动续跑反而完整，只补过期清扫）、假动画（不学）、定时触发空表（本项目 Cron 是真的）、API 裸奔（鉴权限流一并做）、运行锁无看门狗（先不做字段）、版本 diff 只比 ID（复用 Agent 逐字段 diff） | 抄字段设计必须连配套一起做，否则不如不做 |
| 根因诊断方法 | 双 Agent 独立探索 + 关键四项主会话抽查复核；「没法用」= 参数字段错位 + 聊天不接入 + SQL 依赖 + 体验缺陷，非单一 bug | 一类问题一个修法，避免只修表象 |
| 重试轨迹合并单条 NodeTrace | 画布回放按 nodeId 取末次状态，多 attempt 条目制造歧义 | 重试过程写在输出文本 |
| knowledge 节点不包节点超时 | 超时包装挪虚拟线程会丢 Sa-Token ThreadLocal 登录态 | 检索耗时可控；后台链路统一 `fromTrigger=true` 走内部检索 |
| 并行变量合并 | `putIfAbsent` + 按分支起点序归并 | 确定性可复现；同名变量先完成者保留 |
| 后台执行统一 `fromTrigger=true` | 聊天/触发器/API 后台线程都无登录态，knowledge 走 `searchInternal` | W9 遗留隐患的顺手修复 |
| Cron 队列满跳过本周期 | 「宁可丢一次也不雪崩」；分钟级幂等保证同分钟不重复 | 拒绝无上限排队 |
| varsJson 不截断 | 它是 pending_approval 恢复与 `{{节点.output}}` 插值的输入 | 截断破坏执行语义；MEDIUMTEXT 16MB 兜底 + 超长 WARN |
| 纯函数优先拆分 | 先拆表达式引擎 + 图校验器（32 单测锁定），不硬拆节点执行器 | 纯搬运引入大改风险；拆分借单测护航 |
