## 二、两套系统对照（v2 更新）

| 维度 | ForgeAgent（v2 目标态） | SmartCall（参照系） |
| --- | --- | --- |
| 媒体引擎 | **FreeSWITCH**（ESL 控制 + mod_audio_fsc 媒体流 + mod_callcenter ACD） | Asterisk（asterisk-java AMI/AGI + Queue()） |
| 对话引擎 | `forge-voice-engine`：节点引擎 + ASR/TTS SPI + 实时模型适配层（对标移植） | NodeGranter 节点插件 + VoiceModelEnum 三厂商 + RealtimeModelAdapter 四件套 |
| 洞察层 | `agent_cc_call_insight` 统一表（情绪/意图/提取/质检） | 意图/提取/情绪分散在 IVR 节点内 |
| 业务落地 | 8 态状态机 + 工单映射 + 坐席辅助 A1~A5（已交付） | 坐席 UI / SSE / 大屏未实现 |
| 数据模型 | `agent_cc_*`（扩展方向见 §四） | `call_info` 族 + `ivr_call_route` + `ivr_out_task*`（状态机字段设计完整，可作蓝本） |

**选 FreeSWITCH 而非照抄 Asterisk 的理由**（决策 V-1 内含选型）：
1. **ESL（Event Socket）事件面完整**：单一 TCP 通道同时覆盖呼叫控制、事件订阅、outbound 会话接管，比 Asterisk「AMI + AGI + AudioSocket 三套协议」集成面小；Java 侧有活跃维护的 `link.thingsboard:freeswitch-esl` 客户端。
2. **mod_callcenter 原生 ACD**：队列/坐席/分层分配策略/坐席状态内建，替代 SmartCall 在 Asterisk 上手工维护 `queue_members.paused` 忙闲的那套逻辑。
3. **媒体流 fork 原生化**：`mod_audio_fsc`/`mod_audio_stream` 可把通话音频以 L16 PCM WebSocket 双工推给 Java 侧，这正是 ASR/TTS 与端到端实时模型需要的管道（Asterisk 对应能力在社区模块 AudioSocket，生态弱一档）。
4. **Record / uuid_record** 媒体 bug 录音与既有 `RecordingStorage` 契约直接对接。

代价（如实记录）：FreeSWITCH 社区版（1.10.x）需自行编译进 `mod_audio_fsc`（非官方发行模块），该项归入 C1-real；SIP 中继对接运营商需**用户侧落实线路资质与号码资源**（外部依赖，方案不含，V-6 拆分后仅阻塞公网 PSTN 收口）；新增一个部署单元（docker compose 加 FreeSWITCH 服务，资源限制与日志轮转按 §三.4 配）。

**两条现实约束的解法（v2.1）**：
1. **无资质 ≠ 无处测试**：FreeSWITCH 容器 + 软电话分机（Zoiper/MicroSIP 注册内部 PJSIP 分机）即可形成**本机/内网完整回路**——呼入 IVR、音频双工、ASR/TTS、转人工队列全部可真实联调，资质只阻塞「公网 PSTN 呼入/呼出」这一个口。
2. **开发机无 FreeSWITCH 也无 Docker**：WSL2 跑 FreeSWITCH 容器（或云主机 Linux）承载 C1-real；在此之前 FS_MOCK（§三.5）覆盖全部开发与 CI，代码层不产生对真实 FreeSWITCH 的编译期依赖。

## 三、目标架构

### 3.1 拓扑

```
PSTN ──SIP中继──> FreeSWITCH（自建，sofia external）
                    ├── ESL inbound :8021 ──> ForgeAgent FsGateway（控制面：事件订阅/originate/uuid 命令）
                    ├── dialplan socket(outbound) ──> ForgeAgent VoiceIvrServer（IVR 会话接管，阻塞式节点驱动）
                    ├── mod_audio_fsc ws:// ──> ForgeAgent MediaStreamHub（8k/16k L16 双工 → ASR/TTS/实时模型）
                    ├── mod_callcenter（队列/坐席/转人工）
                    └── uuid_record ──> local-fs/OSS（RecordingStorage 契约不变）
ForgeAgent（单 jar，不新增部署单元）
  ├── forge-callcenter        业务层：状态机/幂等/CDR/录音合规/洞察/坐席辅助（已交付，供应商无感）
  ├── forge-callcenter-common 契约层（零依赖纪律不变）
  ├── forge-voice-engine      新能力层：对话引擎（节点/ASR/TTS/实时模型/意图）
  └── gateway: FsGateway（主）+ AiccGateway（备选，保留）
```

### 3.2 事件链路（复用度是本方案的地基）

FreeSWITCH `CHANNEL_CREATE/ANSWER/HANGUP_COMPLETE/CALLCENTER_*` 事件经 ESL 长连接进入 `FsGateway`，归一化为既有 `CsVoiceEvent`（`eventType/workNo/callId/eventGenTime/content` 口径不变）→ 既有 `CsVoiceCallbackGuard`（内网共享密钥简化为连接级认证 + 事件幂等不变）→ 8 态状态机 → 工单映射/转写入库/洞察管道。

**关键点**：自建后事件源从「HTTP 回调」变为「ESL 推送」，但 `CsVoiceEvent` 归一化层不变——Mock fixture 的 `sequence.json` 契约测试模式平移为 **ESL 事件序列回放测试**（回放 FreeSWITCH 事件序列断言状态机目标态，方法论与 V0 完全一致）。

### 3.3 对话链路（对标 SmartCall 的三段式）

| 层 | SmartCall 原型 | ForgeAgent 落地 |
| --- | --- | --- |
| 级联式（ASR→LLM→TTS） | dialplan `AGI(call.agi)` 阻塞线程 + `AsrClient/TtsClient` SPI | dialplan `socket(outbound)` 阻塞会话 + `AsrClient/TtsClient` SPI（自研接口，签名对齐：ASR 消费管道流阻塞返回、TTS 首包放行 `startLatch`） |
| 端到端实时模型 | AudioSocket + `RealtimeModelAdapter` 四件套 + 服务端 VAD | `mod_audio_fsc` 双工 + **四件套接口原样移植**（`RealtimeModelAdapter/Session/Listener/Config` + 工厂按 provider 路由）+ 本地 barge-in（清播放队列 + `cancelResponse`） |
| 编排 | `NodeGranter` 节点插件（15 种）+ JSON 流程定义 + SpEL 上下文 | 节点插件（Bean 名=type 值 + Spring 自动发现）+ `ivr_flow` 表（flow longtext JSON）+ NodeContext 三通道（SpEL/Bindings/Map） |

### 3.4 FS_MOCK 本地开发体系（V-5 核心，无 FreeSWITCH 全链路推进）

设计原则延续 AICC_MOCK：**Mock 只作用于适配层，业务层无感**。自建媒体面下 Mock 面扩大到四层，每层一个接口 + 真实/内存双实现，真实实现按批次交付，Mock 实现随接口同时交付：

| 层 | 接口 | 真实实现（C1-real 起） | Mock 实现（随接口即交付） | 覆盖批次 |
| --- | --- | --- | --- | --- |
| 事件源 | `CsVoiceGateway`（既有三方法） | `FsGateway`：ESL 长连接订阅 → 归一化 | `FsMockGateway`：fixture 事件序列回放（`sequence.json` 模式平移 AICC_MOCK） | C1 起全部 |
| 通道控制 | `ChannelControl`（新增：answer / hangup / uuidTransfer / play / record） | `FsChannelControl`：ESL api/uuid 命令 | `MockChannelControl`：内存记录调用轨迹 + 可编程事件回调（如 play 完成即触发下一事件） | C2/C3 |
| 媒体流 | `MediaStreamProvider`（新增：open 双工 L16 流） | `FsMediaStreamProvider`：mod_audio_fsc WebSocket | `MockMediaStreamProvider`：**可编程音频注入**（WAV/PCM 片段模拟 caller 说话 + 静默段模拟停顿）；TTS 输出落字节缓冲不外放 | C2/C7 |
| ACD/外呼 | `originate` / `transfer`（Gateway 契约扩展） | FsGateway ESL originate / mod_callcenter | Mock：originate 落记录 + 定时回放振铃→接通→挂断事件序列；转人工回放 `CALLCENTER_*` 事件 | C6 |

- fixture 体系：`src/test/resources/mock/fs/` 新增（事件序列 JSON + 音频片段 + 状态机目标态表），与既有 `mock/aicc/` 并列，**成为 FS 事件契约唯一真源**。
- 集成风险收口：mock-first 使 C2~C5/C7 在 CI 全绿后，C1-real 一次性收口真实集成——业务层断言在 Mock 与真实实现间**共用同一套**（V0 已验证的方法论红利）。
- prod 纪律：`FS_MOCK` 仅 dev/test 生效，prod 校验拒绝启动（延续 AICC_MOCK 语义）。

### 3.5 容量与部署口径（V-2）

- 20 万分钟/月 ≈ 日均 6,700 分钟；按每日 10 小时集中 ≈ 平均 11 路并发，30 路上限余量 2.7 倍；FreeSWITCH 单机百路级容量，**30 路为纯软件门禁**（复用 `max-concurrent-calls: 30`、80% 预警、100% 拒绝新呼入），不构成硬件瓶颈。
- docker compose 新增 `freeswitch` 服务（**C1-real 时启用**，开发期不加入常用启动命令）：`mem_limit: 2g, cpus: "2.0"`，json-file 日志轮转 `50m×3`，`networks: [forge]`；ESL :8021 仅内网开放（不映射宿主机端口）；`FREESWITCH_ESL_PASSWORD` 走环境变量，prod 校验器扩展：ESL 密码缺失/为默认值拒绝启动。本机无 Docker（项目环境事实），FreeSWITCH 部署走 WSL2 或云主机 Linux，compose 文件作为部署模板交付。
- 月分钟预算口径从「计费分钟」变为「FreeSWITCH CDR 通话时长」，`CdrReconciler` 数据源从 AICC CDR 换为 `CHANNEL_HANGUP_COMPLETE` 变量，对账逻辑不变。

## 四、增强项清单（P0~P3）

### P0-1 forge-voice-engine：对话引擎对标建设（V-3 主体，替换 v1 的「P0-2 洞察管道」成为最大项）

按 SmartCall 三段式落地，分三步走，每步独立可验证：

**① ASR/TTS SPI + 级联链路（先做，验证全链路）**
- 接口：`AsrClient`（消费 PCM 管道流，阻塞返回识别结果）/ `TtsClient`（`getSampleRate()` + 流式写入 + 首包 `startLatch()`），注册表范式对齐 `VoiceModelEnum`（枚举 code → 工厂路由）。
- 实现：首批接 DashScope（`qwen3-asr-flash-realtime` / `qwen3-tts-flash-realtime`，WebSocket 流式，8kHz 电话采样率直配）；阿里 NLS / 电信留 SPI 扩展位。Whisper/OpenAI 兼容实现作为私有化部署兜底（SmartCall 已验证此路径，8kHz 固定采样）。
- 打断：ASR 实时转写期间用户语音 → 停 TTS 播放（对齐 SmartCall `radio()` 内建打断）；「不允许打断词组」（嗯/哦/好的，精确/模糊匹配）做成配置表 `voice_no_interrupt`。

**② IVR 节点引擎（声明式对话流）**
- 节点集（对齐 SmartCall 15 种，按 ForgeAgent 需求裁剪首批 9 种）：`start / say(播报+SpEL) / answer(收音+打断) / received(DTMF) / intention(意图分流) / agent(知识库问答，接 ForgeAgent 自有 RAG) / condition(SpEL 分支) / transfer(mod_callcenter 转人工) / hangup`；`extract/service/script/sms/child/globeValue/sentiment` 二期补。
- 引擎：`NodeState` 同步循环（SmartCall 核心仅 ~70 行，语义保留移植）+ `NodeContext`（SpEL + JSR-223 Bindings + Map 三通道，预注册工具类）+ 流程定义存 `ivr_flow.flow`（longtext JSON，`@JsonTypeInfo` 多态反序列化）。
- **与 ForgeAgent 既有体系的接缝**：`agent` 节点接自有 RAG（不引 MaxKB）；`intention` 节点接客服域 `CsIntentService` 意图库（语音/文本同库加 channel 维度）；`transfer` 节点触发 8 态状态机 `WAITING_AGENT` 跃迁与工单映射（业务层零改动）。
- 挂机退出：ESL outbound 会话 `CHANNEL_HANGUP` → 中断驱动线程（对齐 SmartCall 的 thread interrupt 语义）。

**③ 端到端实时模型适配层**
- 四件套接口移植：`RealtimeModelAdapter`（provider 路由 + 采样率协商）/ `RealtimeSession`（connect/appendAudio/cancelResponse/speakText/submitFunctionResult）/ `RealtimeSessionListener`（speechStarted/UserTranscript/BotAudio/ResponseDone(truncated)/FunctionCall）/ `RealtimeSessionConfig`（变量渲染用 `StringSubstitutor`）。
- 媒体管道：`mod_audio_fsc` 双工 + 播放节拍器（20ms pacer，清队列实现 barge-in）+ 8k↔模型采样率重采样（SmartCall `upsample2x` 经验：电话 8k 上行前升 16k）。
- 会话编排：单线程控制事件循环 + FSM（CAS 迁移）+ 「用户先开口跳过开场语」仲裁 + 静默巡检挂机（N 次引导后结束语挂断）——语义对齐 SmartCall `RealtimeCallSession`，日志与日志量做减法。
- 首个实现：DashScope Omni（OpenAI Realtime 兼容协议）；自建 vLLM-Omni 留适配位。
- **管理页事实核查**：SmartCall 的 `call_agent/call_model/call_model_voice` 三表模型（provider/model/voice/instructions/greeting/VAD 阈值/静默参数）直接作为 ForgeAgent 语音智能体配置表蓝本。

### P0-2 通话洞察管道（v1 方案主体，保留，依赖不变）

新增 `agent_cc_call_insight` 统一表（唯一键 `(call_id, kind, item_key)`；kind ∈ `SENTIMENT / INTENT / EXTRACT / QA_REPORT`；`segment_until_seq` 增量游标；payload JSON 只存脱敏内容）+ 三执行器（情绪按轮次节流 / 意图挂机后全文双引擎归类 / 信息提取按渠道配置 `extract_keys` 声明）+ 独立 `insightExecutor` 线程池（有界队列 + 硬超时 + 失败 WARN 空转游标，不影响通话主链路）。

**v2 解除的边界**：v1 因「控制面无转接指令通道」将情绪升级限定为坐席建议；自建后 `FsGateway` 可下发 `uuid_transfer`，**负面情绪自动转接升级为可选项**（默认关，`agent.callcenter.auto-transfer-on-negative: false`，开启需同时配置 mod_callcenter 队列名与防抖：同轮次只触发一次）。

### P0-3 双引擎分流规则引擎（保留 v1 设计，执行位置微调）

`agent_cc_route_rule` 表（priority / match_type(REGEX|LLM_ONLY) / pattern / intent_code / action / no_interrupt_words / enabled）。v2 下该引擎有**两个消费点**：IVR `intention` 节点（对话中实时分流）与无 IVR 的「机器人直接应答」模式（转写分片到达后分流）——两种模式并存，按渠道配置选择。

> **C5 已交付（2026-11-13）**：表结构按实施口径更正——原列的 `no_interrupt_words` 与 C2 的不打断词表（`agent_cc_voice_no_interrupt`）语义重叠，改为 `phrase_whitelist`（词组白名单，**文本至少出现其一**才放行，用于把过宽正则收窄到业务认可的表述，例如 pattern 写 `退` 时挡掉「退休/退订」）；另加 `action_arg`（TRANSFER 队列名 / ANSWER 应答键）与 `max_match_length`（量词防护：命中片段上限）。落地组件：`route` 包 `RouteRuleEngine`（priority 升序命中即止 + 60s 缓存 + 三道防护：输入截断/命中跨度上限/坏正则与嵌套量词隔离）、`HybridIntentionClassifier`（`@Primary`，规则 → 语义 → 客服域正则库三级裁决，**模型给出的意图码必须在规则表声明过，动作只来自规则表**，杜绝模型凭空发明动作）、`LlmIntentClassifier` SPI（C5 只交付接口与装配条件 `route-llm-enabled`，无实现降级并 WARN 一次）、`DirectAnswerRouter`（第二消费点：主叫终稿到达即分流，动作同步执行、决策异步留痕 `direct-<segmentId>`）。验证：callcenter 127/127（C5 新 29 用例）、全量 579/579 零失败、DDL 真机幂等（4 条种子规则 + 唯一键）、端到端冒烟 **22/22**（真实 jar：直接应答 2 条决策 = `query_order`→ANSWER_PENDING / `human`→PENDING_NO_CHANNEL，engine=RULE，重放不追加）。
> **踩坑备忘**：①白名单首版按「全部出现」实现，种子规则暴露它要求一句话同时说三个词——运营不可用，改为「至少出现其一」；②`direct-*` 决策与挂机全文意图同属 `INTENT` 类，按 kind 计数会串（冒烟断言必须圈定 `item_key='final'`）；③f-string 里写 JSON 要转义花括号（`{{"direct_answer":true}}`）。

### P1-1 外呼任务体系（v1 的「预置不实施」→ v2 转正式建设）

- 表蓝本照搬 SmartCall：`agent_cc_out_task`（并发数、拨打时段/星期、重拨次数/间隔、去重开关）+ `agent_cc_out_task_call`（明细 + `version` 乐观锁占号 + `linked_id` 回填）。**SmartCall 调度主循环未开源，不可抄**——调度用 ForgeAgent 既有 job 体系（`@Scheduled` + Lock4j 分布式锁），单通发起走 `FsGateway.originate()`（ESL `originate` → `socket(outbound)` 接管 → 进对话引擎）。
- `agent_cc_call` 加 `direction` 列（INBOUND/OUTBOUND），外呼复用 8 态状态机。
- 合规门禁进 `CallcenterProductionReadinessValidator`：拨打时段窗口、单号频次上限、黑名单表、与呼入共享 30 路并发预算（外呼任务并发计入 `max-concurrent-calls`）。
- **v2.1 现实口径**：表模型、调度、合规门禁随 C6 前半段先行（FS_MOCK 验证）；`FsGateway.originate` 真实实现与真实拨号验证延后至资质到位（C6/C9 收口）。

### P1-2 号码池与 SIP 中继（Noop → 正式实现）

- `NumberProvider`（allocate/release/describe）→ `FsNumberProvider`：号码资源表 `agent_cc_number`（号码/归属工作空间/绑定 IVR 流程/状态），对齐 SmartCall「线路 = endpoint」模型（归一化前缀、应答等待时长、归属方字段）。
- `TrunkProvider`（bind/status）→ `FsTrunkProvider`：sofia profile/网关状态经 ESL `sofia status gateway` 读取，中继配置落在 FreeSWITCH 侧，ForgeAgent 只做状态展示与健康告警。
- **外部依赖红线**：SIP 中继与号码资源需运营资质，方案不含资质办理；资质到位前 `trunk-provider`/`number-provider` 保持 noop + FS_MOCK，`FsNumberProvider`/`FsTrunkProvider` 实现随资质进度交付。

### P2 运营增强（v1 保留：质检报告 / 日指标扩维 / 通话画像快照 / 呼损回拨清单）

## 六、明确不做（v2.1）

1. ForgeAgent 不引入 jpower/asterisk-java 等第三方呼叫框架；ESL 客户端只引 `freeswitch-esl` 一个轻量库。
2. 不做坐席 WebRTC 软电话（P3 另立项）、不做多租户（单租户延续）。
3. SIP 中继资质、号码资源、运营商谈判不在工程范围内（外部依赖）；**资质到位前不做任何真实 PSTN 拨号代码上线**，C6/C9 相关真实链路代码随资质进度收口。
4. Mock（`FS_MOCK` provider）不用于生产，prod 校验拒绝启动；Mock 作用于四层适配接口（§三.4），业务层无感。
5. 开发环境不强制本地装 FreeSWITCH——FS_MOCK 是默认开发路径；FreeSWITCH 只存在于 WSL2/云主机的 C1-real/C1-real 后续验证环境。

## 七、决策与取舍记录

| 决策点 | 结论 | 依据 |
| --- | --- | --- |
| 媒体引擎为何选 FreeSWITCH 而非跟 SmartCall 用 Asterisk | ESL 单通道覆盖控制+事件+outbound 接管；mod_callcenter 原生 ACD 免自研忙闲管理；mod_audio_fsc 双工媒体流是实时模型刚需 | §二选型四条 |
| AiccGateway 为何保留不删 | 已交付 + Mock fixture 契约测试资产；D4 中立适配层的兑现场景；云托管作为自建故障时的灾备叙述保留 | 沉没资产是有价值的资产（有测试） |
| 对话引擎为何自研移植而非引 jpower | jpower 与 Spring Cloud/Nacos/MyBatis-Flex 绑定，引即污染单体；SmartCall 引擎核心极薄（节点循环 ~70 行 + 接口若干），移植成本低于集成成本 | 代码实读结论 |
| 洞察管道为何排 C4 而非最先 | v1 时它不依赖媒体面可先行；v2 下对话引擎是主线，洞察的触发源（转写）在 C2 才真实产生，顺序服从依赖 | 依赖方向 |
| 外呼为何并发预算与呼入共享 | 30 路是 FreeSWITCH/中继侧总容量，外呼突破即挤占呼入；D8 门槛语义不变 | V-2 规模口径 |
| script 节点为何首批砍掉 | Groovy/Nashorn 沙箱安全成本 + ForgeAgent 工作流引擎已承接复杂逻辑，避免两套编排 | 既有资产优先 |
| 端到端实时模型为何排 C7 最后 | 级联链路（C2）已满足上线标准；实时模型依赖 mod_audio_fsc 编译与采样率协商，风险独立且大，隔离在尾批次灰度 | 风险隔离 |
| ESL 凭据为何进 prod 校验器 | 8021 端口泄露 = 完整呼叫控制权外泄（originate/挂断/转接全能），比 HTTP 回调密钥更敏感 | 威胁模型 |
| 为何 mock-first 而非按真实链路顺序开发 | 两项现实约束（无资质、无 FreeSWITCH 环境）下，FS_MOCK 四层体系让 C1~C5/C7 全部即时开工且 CI 可跑；真实集成风险集中到 C1-real/C9 两点收口，比散在各批次可控 | V-5/V-6 + AICC_MOCK 已验证的方法论 |
| 内部分机回路为何不算「真实联调降级」 | 回路中音频双工/ASR/TTS/队列/录音与公网链路完全同构，差异只在信令来源（分机 vs 中继）；SmartCall 的开发同样基于内部分机+中继并存，资质缺失只影响最后一跳 | V-6 拆分依据 |
| 无资质期间外呼表模型为何仍建（C6 前半） | 表模型/调度/合规门禁是纯业务层，FS_MOCK 覆盖验证；资质到位后只剩 FsGateway.originate 真实实现一条缝 | 延迟最小化 |
