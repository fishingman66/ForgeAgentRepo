# ForgeAgent 长期记忆体系（六层架构）

> 状态：M1~M4 全部交付（2026-11-07 ~ 11-10）· 适用版本 6.1.0
> 本文描述**实施后的现状**；历史决策与被否方案的取舍记录见第八节。
> 功能总览见根 [README](../README.md)；图谱模块的接入与扩展说明见 [forge-kg/README](../backend/forge-modules/forge-kg/README.md)。

## 一、定位与总览

把「记住用户」做成六层体系：L1 工作记忆管 run 内工具输出，L2 会话摘要管单会话长程，L3 长期记忆管跨会话事实，L4 归档管消息生命周期，L5 治理管合规，L0 统一分配上下文预算。

- 全部落 MySQL + Redis，**零新中间件**；每层降级都不阻断对话主链路。
- 所有增强开关默认关闭，未配置时主链路行为与基线一致（dev 配置已打开）。
- 平台已交付的事实能力，不在本文重复的部分：向量编解码复用 forge-rag 的 `VectorCodec` / `EmbeddingFactory`；图谱本体在独立模块 forge-kg。

```
L0 上下文预算分配（ContextBudgetAllocator，横切）
├─ 系统提示词 → 摘要(L2) → 长期记忆(L3) → 问数/RAG/附件 → 历史
└─ 高优先级块未用满的额度让渡给历史（历史保底 512 tokens）
L1 工作记忆   run 作用域 · Redis · 工具结果压缩 + 按需取回
L2 会话记忆   session 作用域 · token 化历史 + 滚动摘要
L3 长期记忆   agent+user 作用域 · 评分 + 向量混合召回 · 事实键去重
L4 归档       agent_message_archive · 分批转移 · 保留原 id
L5 治理       PII 脱敏 · 遗忘级联 · 配额淘汰 · TTL · 消息归档开关
```

## 二、六层设计与实现

### L0 上下文预算分配

- `ContextBudgetAllocator`（forge-agent）：以 `agent.chat.context-window-tokens`（默认 16000）为总盘，扣除系统提示词 / 用户消息 / 时区说明 / 输出预留后，按「摘要 → 长期记忆 → 问数语义 → RAG → 附件 → 历史」固定优先级分配。
- 未用满的额度自动让渡给历史；超预算块按 token 二分裁剪并标记 `trimmed`；各块实际用量写入 `agent_run_step` 的 CONTEXT 步骤（Trace 可查）。
- KVCache 友好：静态前缀在前；长期记忆块按 factKey 稳定排序，「关联背景」等动态内容固定在记忆块尾部，跨轮前缀不位移。
- RAG(2000) / 附件(3000) 原有预算保留为二级上限，L0 总盘是硬上限。

### L1 工作记忆（run 作用域）

- `RunWorkingMemory`：Redis 键 `agent:run:wm:{runId}:`，指纹白名单 + TTL 1h + 每轮 20 条 + 单条 20 万字符上限；run 结束主动清键。
- `WorkingMemoryGuard`：`AgentTool` 装饰器（注册层生效，6 条执行路径零改动）；工具结果超 800 tokens 时原文入库、上下文替换为「指纹 + 开头 200 字符 + 取回指引」。
- `RecallWorkingMemoryTool`：模型按指纹 + offset/limit 分段取回原文。
- 降级：Redis 不可用 / `working-memory-enabled: false` 时退回原样透传。
- 关键实现事实：AgentScope 2.0.4 的 `ToolResultBlock.text()` 默认状态是 `RUNNING` 而非 `SUCCESS`，压缩判定必须接受 RUNNING/SUCCESS（字节码实测，见第八节决策表）。

### L2 会话记忆（token 化历史 + 滚动摘要）

- 历史：预加载上限 `history-preload-limit`（默认 80 条），按 `historyBudget` 从新往回裁剪，`history-max-turns`（默认 40）作条数兜底，始终保留最近一条；过滤摘要水位之前的消息。
- 摘要：`agent_session.summary_text` + `summary_upto_msg_id`（水位 CAS 推进，重复投递不覆盖）；未摘要消息累计超 1500 tokens 时异步生成（Agent 绑定模型，最近 4 条保持原文，调试会话与重新生成不触发）；失败静默下轮重试。
- 依赖：摘要需要 Agent 已绑定模型；未绑定时只保留 token 化裁剪。

### L3 长期记忆（评分 + 向量混合召回）

**存储**：MySQL 向量列。`agent_memory` 加 `embedding BLOB` + `embedding_dim` + `embedding_model` 三列，float32 小端存储，检索为应用层余弦、O(n) 全扫（`scan-limit` 默认 5000，超限告警）。不新增数据源、不新增表；pgvector/milvus 只留枚举扩展位（见第八节决策）。

**写入**：抽取落库后异步向量化（独立有界线程池，队列满丢弃）+ 每轮对话前补偿扫描双保险。模型换版：旧向量按 `embedding_model` 过滤，内容变更行标记 `stale`，由补偿扫描重算。

**召回**：评分召回兜底 + 向量召回 topK（默认 20），两路按 factKey 去重融合：`0.6×语义相似度 + 0.4×现状评分`。降级纪律：向量服务不可用、维度不符、零向量、配置关闭时回退纯评分，对话不中断。

**评分**（`scoreOf`，与配额淘汰同一口径）：importance + 命中反馈（封顶 + 5 分钟节流）+ 时间衰减。

**隔离与脱敏**：候选池与冲突替代按 agent+user 隔离（M1.5 D1）；抽取提示词约束 + 落库/读侧双层 PII 脱敏（D5）；注入结果与语义检索读侧再兜一层。

### L4 归档（消息生命周期）

- `agent_message_archive` 与 `agent_message` 同构，保留原 id 便于对账，冗余 `owner_user_id`（供遗忘级联）与 `archive_reason/archive_time`。
- `MemoryGovernanceService.runArchive`：会话 `last_msg_time` 超 `archive-retention-days`（默认 180）且未置顶 → 分批 `INSERT...SELECT`（单批 500、单次最多 20 批）→ 按归档表 id 对账删主表。
- 归档时间戳统一截断到秒（MySQL DATETIME 无纳秒，对账等值比较必须口径一致——e2e 实测修正）。
- 归档任务用 Spring `@Scheduled` 而非 SnailJob：消息归主域、天级周期，不为它接调度平台。摘要/抽取只回溯近期消息（水位之后），归档不触达，暂无「读归档」调用方。
- 实现位置在 forge-memory，用纯 SQL Mapper 操作 `agent_message` / `agent_session`——依赖方向是 agent → memory，不能反向；表到表转移不需要实体。

### L5 治理

| 能力 | 现状 |
| --- | --- |
| PII 脱敏 | 抽取提示词约束 + 落库正则扫描（手机号/身份证/邮箱）+ 读侧兜底，三层 |
| 用户级遗忘 | `DELETE /agent/memory/user/{userId}/forget?agentId&confirm=FORGET`；级联顺序：记忆（含向量三列，@Delete 物理删绕过 @TableLogic）→ `KgService.deleteScope(KgScope.agent)` → 两张归档表按归属删；confirm 精确匹配，平台级记忆不可遗忘 |
| 容量配额 | `agent_info.memory_quota`（NULL/0=不限）+ 全局默认 `memory.governance.default-quota`；抽取写入前先淘汰（保证最新事实进得来）+ 治理任务盘点；按 `scoreOf` 最低分进归档（`archive_reason=QUOTA`），不物理删 |
| TTL | `agent_memory.expire_at`（NULL=永久）在注入与向量召回双过滤；`ttl-days>0` 的隐式过期由治理任务归档兜住（注入侧最多滞后一个扫描周期） |
| 消息归档开关 | `memory.governance.archive-retention-days`（0=关闭归档步） |

治理总开关 `memory.governance.enabled` 默认关闭；`scan-ms` 必须 >0（@Scheduled 周期配 0 会让应用起不来，开关与周期分离）；`POST /agent/memory/governance/run` 手动触发不受 enabled 限制。

## 三、数据模型（当前实际）

| 表/列 | 说明 |
| --- | --- |
| `agent_memory` | 核心记忆表：fact_key 冲突替代、importance、hit_count、`embedding/embedding_dim/embedding_model`（向量三列）、`expire_at`；逻辑删除 del_flag |
| `agent_session` | `summary_text` / `summary_upto_msg_id`（摘要水位）、pinned、last_msg_time |
| `agent_message_archive` | 消息归档（同构 + owner_user_id + archive_reason/time） |
| `agent_memory_archive` | 记忆归档（TTL/QUOTA 淘汰留痕，向量不归档，原 id 保留） |
| `agent_info.memory_quota` | 每 agent+user 记忆条数上限（NULL/0=不限） |
| `kg_node` / `kg_edge` | 图谱两表，见 forge-kg README |

SQL 脚本（幂等可复跑）：`agent_p2_memory.sql`（主表）、`agent_p3_m1_session.sql`（摘要水位）、`agent_p3_m2_memory_vector.sql`（向量三列）、`agent_p3_m4_memory_governance.sql`（归档两表 + expire_at + memory_quota + 指标表）、`forge_kg_core.sql`（图谱）。

## 七、明确不做与后置

1. Postgres + pgvector **后置**（MySQL 向量列已满足，出现明确需求再接，枚举位保留）。
2. Neo4j **后置**——`KgStore` SPI 已就绪，新增 `backend()="neo4j"` 实现并注册 Bean 即切换。
3. 不做跨 Agent 共享记忆池；不做图谱画布可视化；不迁移 RAG 向量后端。
4. 归档消息暂无读取方（摘要/抽取只回溯水位之后），「先主表后归档」的统一读门面等真实需求出现再做。
5. 节点半衰 / 边减权衰减**未实施**（当前只有遗忘级联与治理清理），需要时基于治理任务扩展。

## 八、决策与取舍记录

| 决策点 | 结论 | 依据 |
| --- | --- | --- |
| 向量存储（2026-11-10） | MySQL 向量列，pgvector 后置 | 复用 RAG 已验证的 `MysqlVectorStore` 模式，dev 零外部依赖跑通；pgvector 是运维单点，可选件纪律照旧 |
| embedding 复用方式 | `EmbeddingFactory.forModel` 直接复用 forge-rag，**不搬包下沉** | 下沉 core 需迁移约 4 文件且 forge-rag 不依赖 memory 无循环，改动面 1 行 pom；出现第三个复用方再下沉 |
| 图谱归属（2026-11-10） | 抽出独立模块 forge-kg，通用 `(scope_type, scope_id, user_id)` | 图谱还要服务客服领域能力；`user_id=0` 作共享级（不用 NULL：MySQL 唯一索引对 NULL 不去重会让 upsert 失效） |
| 图存储 | MySQL 两表 + 1 跳邻接，Neo4j 只留 SPI | 单域图几百节点两表够用；未实现的后端按关闭处理并告警一次，绝不半启用 |
| 压缩判定 | 接受 `RUNNING`/`SUCCESS` | AgentScope 2.0.4 `ToolResultBlock.text()` 默认 RUNNING（字节码实测），按 SUCCESS 判定会让压缩永不生效 |
| 压缩挂点 | `AgentTool` 装饰器（注册层），不用内核 Hook | 6 条执行路径零改动生效，不依赖事件语义 |
| 归档调度 | Spring @Scheduled，非 SnailJob | 天级周期不值得接调度平台；`scan-ms` 必须 >0（配 0 抛异常导致起不来），开关与周期分离 |
| 对账时间戳 | `truncatedTo(SECONDS)` | DATETIME 无纳秒，`archive_time = stamp` 等值比较口径必须一致（e2e 实测修正） |
| 记忆 VO 映射 | 手工映射，不用 MapstructUtils | 其静态初始化走 hutool SpringUtil 拿 BeanFactory，无 Spring 环境直接 ExceptionInInitializerError |
| PII 边界 | 打码留在业务域 | forge-kg 零业务依赖，不依赖 CsPiiMasker；三元组组装前由调用方完成 |
