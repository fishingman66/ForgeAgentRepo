# 权限模型说明

## 1. 两级隔离

权限分两级：平台级与工作空间级。平台级由超级管理员掌握，能看见所有工作空间的数据；
工作空间级由空间成员按角色划分，角色分为管理员、开发者、访客三种。
资源带 `workspace_id` 字段时归该空间私有，字段为空表示平台共享，所有空间都能读。

## 2. 读写约束

全局资源（`workspace_id` 为空）只有超级管理员可以新增与修改，普通用户只能读；
空间私有资源由本空间的管理员与开发者维护，访客只读。
创建后归属不可变更，也不允许把私有资源降级成共享资源，这是为了避免凭据被悄悄提权。

## 3. 校验入口

所有可见性判断收敛到一个守卫类里，提供校验可读、校验可写、拼接可见性条件三个方法。
列表查询必须把可见性条件下推到 SQL，不允许先全量查出再在内存里过滤，
否则分页总数会失真，用户会看到"第二页突然变空"。

## 4. 会话与令牌

登录态用 Sa-Token 管理，令牌放在 `Authorization` 头里，前缀是 `Bearer`。
坐席端带令牌的请求还必须额外携带 `clientid` 头，值固定为平台分配的设备标识，
缺少这个头会直接返回"认证失败，类型 -100"。
访问凭证类接口前需要先调用登录接口拿到令牌，令牌有效期默认十二小时，支持无感刷新。

## 5. 常见误用

把全局知识库交给普通开发者维护是最常见的误用：全局库对所有空间可读，一旦写错会影响全部租户。
正确做法是为每个空间建私有知识库，需要共享时再复制内容过去。
另一类误用是给访客角色分配开发者权限，这会让只读用户获得修改配置的能力。
