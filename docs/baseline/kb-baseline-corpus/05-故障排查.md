# 故障排查手册

## 1. 先看三处

排查顺序固定：先看应用日志有没有 ERROR 行，再看接口返回体里的 code 字段，最后看数据库状态。
注意业务失败也会返回 HTTP 200，只看状态码会把失败当成成功，必须解析响应体里的 code。
日志里每条请求都带耗时，超过两秒的请求要重点看下游依赖的耗时分布。

## 2. 知识库检索为空

先确认知识库状态是不是正常，再看文档状态是不是可用，最后看分块数与向量条数是否一致。
文档显示可用但向量条数为零，说明向量写入失败过，补偿任务会把状态刷回来，也可以手动重建。
如果只有关键词能搜到、语义搜不到，先检查嵌入模型配置是否还能正常调用。

## 3. 对话卡住不返回

先看是不是首字延迟高：模型首 token 慢会把整轮回答拖住，查看链路追踪里的模型耗时与首字时间。
再看有没有查询改写超时，改写是增强项，超时应该退回原句继续，而不是让整轮失败。
最后看流式连接是否中断，断线续传依赖事件缓冲，缓冲被清空会导致重连后拿不到历史增量。

## 4. 权限与跨空间访问

访问其它空间的资源会返回"知识库不存在或无权访问"，这是刻意模糊化的提示，避免泄露资源是否存在。
内部链路调用检索时不带登录态，必须显式传入调用方工作空间 ID，否则跨空间校验会直接拒绝。
坐席端调用带令牌接口时缺少设备标识头，会返回固定的认证失败类型码。

## 5. 常见错误码

认证失败类型 -100 表示令牌或设备标识有问题；参数校验失败返回 400 并带字段名；
资源不存在返回 404 但提示语是统一文案；服务内部异常返回 500 并附带一个错误编号，
拿这个编号去日志里搜索能定位到完整堆栈，这是最快的定位方式。
