# 部署与运行手册

## 1. 运行形态

平台采用单体后端加前端静态资源的部署形态。后端入口是 `forge-admin` 模块，打包产物为 `forge-admin.jar`，
启动时用 `-Dserver.port=8080` 指定端口；若环境变量里注入了 `SERVER_PORT`，会覆盖配置文件中的值，
导致实际监听端口与预期不一致，排查时先用 `netstat` 确认监听端口再判断服务是否启动成功。

## 2. 配置分层

配置文件分三层：`application.yml` 放公共项，`application-dev.yml` 放本地开发项，`application-prod.yml` 放生产项。
生产专属开关包括数据库连接池上限、慢查询阈值、审计日志保留天数。修改生产配置必须同时更新部署仓库里的同名文件，
否则下次发版会被覆盖回去。

## 3. 依赖组件

必需依赖只有两个：MySQL 8.0 以上版本与 Redis 6 以上版本。可选项是向量库 Milvus，
不安装时把 `rag.knowledge.vector-store` 设为 `mysql`，向量会存进分块表的二进制列，检索在应用层计算余弦相似度。
MySQL 的全文索引需要 ngram 分词器，建表脚本里已经带上 `WITH PARSER ngram`。

## 4. 启动顺序

正确顺序是先起 MySQL、再起 Redis、最后起后端。后端启动时会校验数据库结构与种子数据，
发现缺表会打印建表提示但不会中断启动；Redis 连不上时缓存相关功能降级，登录态校验也会失败。
启动完成的标志是日志里出现 `Started AdminApplication` 与监听端口两行。

## 5. 日志与临时目录

应用日志默认输出到控制台，容器部署时挂载到 `/app/logs`。临时文件统一放在工作目录下的 `temp` 子目录，
不要写到系统临时目录，否则容器重启后残留文件无法清理。文件上传的原始件默认落在 `./data/knowledge`，
按知识库 ID 分子目录存放。
