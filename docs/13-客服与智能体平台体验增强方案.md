# ForgeAgent 客服与智能体平台体验增强方案（体验层 · 产品化缺口 · 平台能力）

> 状态：**全部交付**（E1~P3 五批 + 14 批复核追加，2026-11-20 ~ 11-23）
> 参照对象：一套开源客服与智能体系统（下称**参考系统**），仅用于交互形态与产品化能力的横向参照，不引入其技术组件、数据模型或代码。
> 本文四个部分：**第一部分** 现状评估与差距判定；**第二部分** 分层方案（层 A~D + F1~F4 提前项）；**第三部分** 批次交付与复核整改；**第四部分** 已知边界、后续候选与决策记录。
> 结论：**ForgeAgent 的后端治理（渠道安全、工单状态机、工具护栏、灰度、评测回流、六层记忆、指标口径）系统性更强，差距集中在「客户可感知的体验表现层」和少数产品化能力缺口**——因此本方案不做能力复制，只做两件事：把已有强能力用最佳体验呈现出来，补真正缺的产品化能力。
> 范围衔接：客服业务域主方案（七态工单 / ACD / 合规 / 坐席辅助）见 [02-智能客服域](02-智能客服域.md)；对话内核架构见 [11-智能客服架构对标与增强方案](11-智能客服架构对标与增强方案.md)；横切治理见 [12-JdbcTemplate 裸 SQL 治理方案](12-JdbcTemplate裸SQL治理方案.md)。
> **编号说明**：本文 `A1~A5` 指**层 A 的体验项**，与 02 篇第三部分「坐席辅助 A1~A5」同名不同义；`A-1~A-7` 是 2026-11-22 第二轮复核后新增的下一批编号，与两者都不重叠。

# 第一部分 · 现状评估与差距判定

## 一、评估口径

两个系统不在同一产品阶段，脱离定位逐项抄功能会做错方向。先对齐五个维度的差异：

| 维度 | 参考系统 | ForgeAgent | 对方案的含义 |
| --- | --- | --- | --- |
| 定位 | 面向跨境场景的商业化开源产品（SaaS 形态为主），客户-facing 体验是核心卖点 | 面向企业的**私有化平台**，后端治理深度是核心卖点 | 不借鉴其演示数据与半成品模块，只借鉴体验表现层做法 |
| 前端 | 组件化 SPA + 可视化画布 + PWA，挂件多形态、品牌定制、宿主上下文桥 | Vue3 + Element Plus + 自研 SVG 画布；**访客端是原生 HTML** | 体验差距几乎都在前端表现层 |
| 数据层 | 关系库 + 数据库内原生向量扩展 | MySQL + 应用层向量列（BLOB）+ 图存储模块 | RAG 已达标（HitRate@5 93.33%），不换库、不换向量方案 |
| 工单 | 工单 + AI 根因调查 + SQL 只读围栏 | 七态工单 + ACD + 质检 + 只读 SQL 工具 + 审批门 | 工单治理更强，缺的是 **RCA 编排封装** |
| 多渠道 | 9 种以上海外渠道（即时通讯、社媒私信、邮件、短信、电商平台）+ 电商 CRM | 网页挂件 / H5 / 公众号 / 企微 / OpenAPI / 电话 | 渠道广度是真实缺口，但需按国内场景取舍 |

**差距判定四级**：**优于参考实现**（Forge 更强）／**相当**／**体验落差**（后端有、前端没做好）／**缺口**（没有）。

差距归为三类，落地分四层：**体验落差**（层 A，后端已具备、前端没消费，最高性价比）、**产品化缺口**（层 B，需新建）、**平台能力增强**（层 C，两边都有但可更强），再加一层横切的**工程健壮性与全球化**（层 D）。

# 第二部分 · 分层方案

> 本部分记录**方案态设计**（每项给最优解与边界，不给「能跑就行」的将就解）；实施期的路线修正与被否方案见第四部分「决策与取舍记录」。

## 三、层 A · 体验表现层（后端能力已具备，最高优先）

共同特征：几乎不改后端契约，收益/成本比最高。

| 项 | 能力 | 现状 → 方案要点 |
| --- | --- | --- |
| A1 | 访客逐字流式 + Markdown | 后端 `POST /chat-api/{code}/sessions/{cid}/messages/stream` + `RunEventBuffer` 续传齐备；访客页是原生 HTML，整段 `POST /messages` + 5s 轮询。→ 改走流式端点逐字追加，`run_id` 建游标、断线 `/events?after=` 补齐；打字点 + 光标 + 白名单 Markdown +「正在检索知识库」；`stream-enabled=false` 回退整段 |
| A2 | 挂件 2.0 | `cs-widget.js` 仅右下角圆按钮 + 360×520 iframe，主色写死，仅 `data-title` 一个参数。→ **保留 iframe 隔离**，配置改后端下发（`GET /chat-api/{code}/widget-config`，运营在渠道页可视化配置）；`postMessage` 宿主上下文桥（白名单 origin，只透传 externalUserId/pageUrl/orderId）；未读徽标、开场语、气泡 + 侧边栏两形态 |
| A3 | 坐席输入区增强 | `ChatPanel.vue` 裸 textarea，无 `/`、`@`、润色、内部备注。→ 叠加交互层不换组件库：`/` 快捷话术（复用 ACTIVE FAQ）、`@` 提及坐席（生成内部提醒）、AI 润色/中英互译（复用既有模型门面）、**内部备注走 NOTE 事件不进访客 SSE** |
| A4 | 运营看板图表化 | 6 指标卡 + 12 列日表，口径齐全但零图表；平台侧看板已有 echarts 6.1。→ 抽公共图表组件，加双轴趋势 / 渠道饼图 / 服务漏斗三类图，只读 `agent_cs_metric_daily`，**不改聚合与指标口径** |
| A5 | Agent 创建向导 | 无 onboarding，`agent/agent/index.vue` 一张长弹窗表单，配置散落多页。→ 5 步向导（命名 → 选模型 → 提示词接 C4 → 挂知识/工具 → 测试发布），`el-steps` 复用市场页样式；不替代高级配置页 |

**被否**：A1 继续在原生 `index.html` 手写 SSE（无 Markdown、无续传，与平台端越走越远）；A2 照抄参考实现的多形态重写（丢 iframe 隔离，且无对应业务场景）；A3 引入 Tiptap 等富文本编辑器（新依赖 + 与 Element Plus 割裂）；A5 把长表单整体重构为向导（高风险、破坏存量习惯）。

## 四、层 B · 产品化能力缺口（需新建）

| 项 | 能力 | 方案要点（含边界） |
| --- | --- | --- |
| B1 | 公开帮助中心 | **同进程按路径分发**（`/help-api/{channelCode}/**` 公开只读），绝不新建部署单元；内容源直读已发布文档 + 已生效 FAQ，**不建 CMS**；sitemap/robots 动态生成；文章反馈按 IP + 文章 + 日去重并写知识缺口飞轮；域名/主题走渠道级配置。边界：站内搜索（F1）与多语言（F3）同期交付 |
| B2 | 全站摄取 | 在既有 `ExtSourceConnector` SPI 下加 `SitemapCrawlerConnector`：解析 sitemap/sitemapindex 递归 → 逐页 `SsrfGuard` → 复用 `importText`（MD5 去重）+ `uq_ext_item` 幂等；**不引爬虫框架**；对象存储/协作平台两个空壳要么补齐、要么登记阶段即拒，不留「可保存但同步必失败」的假实现 |
| B3 | FAQ 答案自动生成 | 以待审问题的历史坐席优质回复或 RAG 命中片段作 reference，生成候选答案 + 引用，仍进人工审核（`PENDING`）不自动生效；复用 LLM 裁判打分，低于阈值不生成；加成本估算端点。把数据飞轮从「半自动补问题」补成「全自动候选 + 人工把关闭环」 |
| B4 | AI 工单根因调查（RCA） | **不新建 AST 解析器**（只读护栏已够）：两张表（`agent_cs_investigation` + `_evidence`）+ 工单上下文 → 模型提最多 3 条假设（各附只读 SQL）→ 逐条取数（白名单 + 只读 + 行数/超时熔断，全量审计）→ 证据链报告 → 坐席确认后才回填 |
| B5 | 渠道广度（克制） | 只补两个国内刚需：① 邮件工单（Email → 会话，复用 OpenAI 兼容端点思路）；② 企微**加密模式**（`EncodingAESKey` + AES-CBC，02 篇已知限制 1）。跨境渠道列「出海时立项」 |

## 五、层 C · 智能体平台能力增强

| 项 | 能力 | 方案要点 |
| --- | --- | --- |
| C1 | 工作流节点补齐 | 补 `form`（结构化表单收集）/`wait`（等待）/`human_transfer`（转人工）三节点：form 复用槽位结构、human_transfer 复用客服转人工契约（缺会话 fail-closed）、wait 复用审批的暂停/续跑（`resumeWaitRun` 语义已存在）；落地页/护栏类节点判低价值不做 |
| C2 | MCP STDIO 传输 | 按 `StdioClientTransport` 补分支，配置加 `command`/`args`/`env`（密钥走环境变量）；**附带补安全债**：`url` 与 `command` 都需 SSRF / 命令注入校验（仅允许预注册白名单可执行、禁 shell 元字符） |
| C3 | 多模型 + 自助带 Key + Key 加密 | 三小步按收益排序：① **Key 加密（安全必做）**，存量明文一次性迁移，输出仍掩码；② 自助带 Key（空间管理员填自己的 Key，沿用 `ResourceAccessGuard` 空间隔离，不做面向终端用户的注册流程）；③ 原生协议只在兼容层效果明显差的模型上补，**保留 OpenAI 兼容为默认** |
| C4 | 指令自动生成 | 输入 Agent 名称/用途/语气/边界 → LLM 生成 system prompt 草稿 + 结构化 sections（角色/任务/约束/输出格式）→ preview 由人确认 → 采纳走既有版本链（contentHash 后端算）。与 A5 向导联动 |
| C5 | 技能市场（选做） | 复用 Agent 市场的 Listing/Install/Review 扩展到 Skill；参考系统也无独立技能市场，**非刚需** |

## 六、层 D · 工程健壮性与全球化

| 项 | 现状 | 方案要点 | 去向 |

## 七、F1~F4 · 把「时机判断」从禁令里解绑

原「明确不做」把两类性质不同的东西混在一张清单：一类是**工程红线**（碰了破坏正确性/安全/已达标基线），另一类是**当时的成本与定位判断**。后者条件变了就该复评，否则白丢可用性。

| 原禁令 | 复评结论 | 去向与方案要点 |
| --- | --- | --- |

## 十一、顺带修掉的既有缺陷

非本方案引入，但都值得跨会话记住——其中多处属「静默失效」，只有真跑链路才会暴露：

1. `@Scheduled(fixedDelayString="${x:0}")` 配 0 会抛异常导致应用起不来 → 必须独立 enabled 开关。
2. MP `updateById` 忽略 null 字段 → 置空必须 `LambdaUpdateWrapper.set`。
3. 工单状态机缺「退回池」两条跃迁边；会话路由判定不能用「agentSessionId 是否已写入」。
4. **挂件配置保存不生效**：`Channels.vue` 有 `widgetTheme/widgetMode/widgetWelcome/widgetConfig` 表单，但 Bo/Vo 都没这四个字段，`MapstructUtils.convert` 直接丢掉——运营配置一直没写进库、列表也回显不出。
5. **技能安装/卸载缺 Agent 归属校验**：只校验技能可见性，任意登录用户可把技能绑到**别人空间的 Agent** 上（等于改他人配置）；补 `agentMapper.selectById` + `resourceGuard.assertWritable`。
6. **SMTP 从未携带渠道凭据**：`JakartaMailTransport` 设了 `mail.smtp.auth=true`，却从未把 `smtpUser/smtpPassword` 交给 Session、也没有 Authenticator——AI 自动回信与人工回信都会在建连阶段失败，原单测全 mock 传输层所以从未暴露（fake e2e 一接上就报 `no password specified?`）。
7. 帮助中心公开入口只调 `require()`，`checkRateLimit` 只出现在访客/兼容端点——IP 限流实为缺失。
8. 挂件 `postMessage` 只发不收；监听 `unread` 但 iframe 从不发送，徽标恒 0。
9. `chat_done` 只取 `content`，citations 既不下发也不渲染。
10. 静态 sitemap 的 `<loc>` 是相对路径，全前端无 `hreflang`。
11. `AgentModel.apiKey` 明文存库仅输出掩码，`mybatis-encryptor.enable: false`（安全债）。

# 第四部分 · 已知边界、后续候选与决策记录

## 十三、已知边界（按主题归并）

### 13.1 访客端与坐席端

1. 访客页 Markdown 是白名单子集（粗体/行内码/代码块/链接/列表/换行），与平台端 markdown-it 全量能力不一致——零依赖约束下的有意取舍。
2. 两份 SSE 解析并存（访客页内联 + 平台端 `sse-events.ts`），后端新增客服专有事件需两端同步；两端都对未知事件静默忽略。
3. 访客页续传只做 `/events?after=` 补齐，未做平台端那种按 `runId` 的多次重连循环。
4. 未读徽标只覆盖「面板收起 + 页面仍在」，标签关闭后的离线消息不补算（无服务端未读游标）。
5. 上下文桥 iframe 最多等宿主 800ms，超时用本地 visitorId 建会话；宿主迟到不改造已建会话（避免一号两会话）。
6. `allowedOrigins` 为空时不校验 origin（兼容旧嵌入），生产须显式配置。
7. 情绪趋势是「最新分 + 连击数」不是逐轮曲线；每轮情绪事件未落库（每轮消息时还没有工单，而 `ticket_event` 的 `ticket_id NOT NULL` 挂不上）。
8. 营业时间需运营填 JSON（已加输入框），无可视化周视图；时区默认 Asia/Shanghai。
9. 坐席工作台与看板仍有 76 / 44 行硬编码中文（管理端 i18n 维持不做）；`el-table` 11 列窄屏仍横向溢出，移动端是「能用」不是「好用」。
10. @提及已读用单列 `read_flag` 表达，不做跨设备游标云端同步；同一坐席被多条备注 @ 会产生多条事件（预期行为）。
11. AI 润色/翻译依赖渠道绑定 Agent 的模型，未配置或调用失败时保留原文并提示，不阻断回复。
12. Agent 创建向导第 5 步不含内嵌测试会话（创建后到对话页验证）；草稿态保存与「创建并发布」两条路径均已打通。

### 13.2 帮助中心与公开面

13. 一篇文章只有一种 locale，文章页不做跨语言 alternate；SPA 动态 `<link>` 依赖爬虫执行 JS，不执行 JS 的爬虫以 `/help-api/{code}/sitemap.xml` 的 `xhtml:link` 为准。
14. 品牌域名只校验格式 + DNS 可解析（四态），不做 CNAME 记录类型校验（需额外 DNS 库）与 SSL 签发（需 ACME 编排）；邀请为「登录后自动接受」，完全免登录接受不做（令牌不绑 userId，等于链接即账号接管）。
15. SaaS 隔离正确性完全依赖 `ResourceAccessGuard` 覆盖面，新增资源域必须同步纳入并回归。
16. 无统一域名，静态 sitemap 的相对 `<loc>` 需按实际部署替换（动态端点仅作兜底与多语言互链）。

### 13.3 工作流与 HITL

17. HITL 重放只覆盖 http/sandbox/sql 三档且是 **at-least-once**：崩溃前已执行但 DONE 未落库会再执行一次（POST 类 http 工具需注意重复副作用）；MCP 需重建连接、丢失服务端会话态，仍走 NEED_MANUAL。
18. 重放绕过 `CsToolGuard`（与既有回调同口径），建议 sql 工具只绑只读账号/SELECT 白名单数据源。
19. wait 超时默认终止，配 `timeoutPayload` 才续跑；form 节点无 `timeoutMinutes`，不纳入超时扫描。
20. `human_transfer` 依赖 `inputs.conversationId`（工作流上下文不含会话 ID），缺失即失败，不产假工单。
21. RCA 未做成「画布可调的模板」：`ToolAssembler.buildForWorkflow` 传 null 装饰器、审批强制 `auto`，工作流取数会绕过 `CsToolGuard`，故改为服务内直调 `SqlQueryService`（审计粒度更细，但运营改不了编排）。

### 13.4 安全与凭据

22. C3-1 只做在线渐进加密（存量明文原样返回、新写入才加密），**未做全量迁移脚本，「切仅密文」未执行**；`AGENT_KEY_SECRET` 未配置时用内置默认值，生产上线清单必须显式覆盖。
23. MCP stdio 白名单是「整串全等 + basename 忽略大小写」双口径，任意目录同名 wrapper 都能命中；**脚本内容完全不在审计范围**（validator 只读配置字符串）。生产硬要求：唯一脚本名 + 严格 `argsPatterns` + 最小权限 + 只读挂载。command 改成 wrapper 后 `commandName` 变化，原先配在 `node`/`npx` 上的 argsPatterns 会失效，解释器内联码闸整闸跳过。
24. `argsPatterns` 未配置时，`npx -y <任意包>`、`python <任意脚本>` 仍可执行任意代码——不能把「命令名」当安全边界。
25. `SsrfGuard` 只在 verify 时解析一次，`HttpClient.send` 再解析，DNS rebinding 未根治；robots.txt 拉取失败按 fail-closed 拒绝整批（目标站长期 5xx 则该来源无法同步）。
26. 企微 `EncodingAESKey` 变更后历史密文无法解（密钥轮换固有约束），需运营在企微后台同步更换。
27. A-3 只做单层线程头（`In-Reply-To` 与 `References` 写同一 ID），多层 References 链不重建；回信不受 `emailIngestEnabled` 约束，但受渠道 status/replyEnabled 双重约束。
28. PWA Service Worker 不缓存任何 API 响应（访客消息含 PII 不落盘），「离线看历史会话」实际是「离线能开页面并看到离线提示」。

### 13.5 部署与环境

29. **存量库需按新列补 `ALTER`**：`agent_cs_channel`（business_hours_json / widget_lang / encoding_aes_key / corp_id / channel_config）、`agent_cs_conversation`（source_url / order_id）、`agent_cs_message_receipt`（raw_message_id）、`agent_cs_ticket_event`（read_flag / target_user_id）、`agent_workflow_run`（pending_deadline）、`agent_workspace`（domain_status / domain_verified_at）、`agent_knowledge_document`（locale）、`agent_mcp_server`（command / args / env，url 可空）、`agent_approval`（tool_id / tool_def_snapshot）、`agent_model.api_key` 长度。DDL 真源只有 `init/01-schema.sql`。
30. 技能市场只做发现 + 绑定，无发布/审核/评分；`install` 语义是绑定到 Agent，不是复制副本到本空间。
31. B2 的 `maxDepth` 是 **sitemap 自身嵌套层数**，不做页面内链接扩张；同步在单事务内（≤50 页 / 120s 预算）；邮件按发件人地址归并会话，回信固定 `Re: 原主题`。
32. 指标口径：漏斗走实时会话表、指标卡/表格走 `metric_daily` 物化表，重建未跑时两者可能不同步（漏斗仍实时准确）。
33. `pnpm build` 重复执行时 Vite 清空 `dist/assets`（635 文件）会触发沙箱批量删除保护（阈值 50），改用 `--emptyOutDir=false` 复验——非代码问题。

## 十四、架构级与外部资源（不作为待办）

1. **DNS rebinding 根治**：JDK HttpClient 无 pin 接口，需连接级 pin IP。
2. **exactly-once HITL 重放**：`action_log` 需 PENDING 两段式状态机。
3. **MCP 原生 working-directory**：`StdioTransportConfig` / `ServerParameters` 均无 cwd 字段，等价方案已走 wrapper 脚本。
4. **anthropic-java 3.x**：需同步升级 agentscope 并重编其扩展类，属框架级升级；2.75.0 已是 2.x 终版。
5. **真实企微企业 / 外部邮箱 / 真实模型 Key 的端到端 e2e**：外部账号资源；本地 fake e2e 只覆盖编排，不冒充真实 e2e。
6. **支付 / OCR**：参考系统同样未实现，不构成本方案的缺口项。

## 十五、下一批候选

**A 档已清零**，只剩 A-6 的三条加固选项（决策项，本批未擅自实施）：

| 选项 | 内容 | 代价 |
| --- | --- | --- |

## 十六、决策与取舍记录

| 决策点 | 结论 | 依据 |
| --- | --- | --- |
| 只借鉴形态、不移植实现（ADR-01） | 只借鉴交互形态与产品化能力形态，实现全部基于现有技术栈 | 零技术栈漂移；不追求功能项逐一对齐，对齐的是用户可感知价值 |
| 访客页共享语义、不共享代码（ADR-02，**实施形态已更正**） | 访客页是 `public/` 下原生 HTML、不走 Vite 构建；后端 SSE 事件也不同构（模型路径 `delta{payload.text}`、FAQ/缓存/兜底路径 `chat_chunk{payload.content}`）→ 内联零依赖解析 + 白名单 Markdown，兼容两种增量、`chat_done.content` 权威收口，平台聊天页零改动 | 原决策「抽公共 sseParser 复用」物理上不可行；代价是两份解析代码，新增事件需两端同步 |
| iframe 隔离是特性（ADR-03） | 保留 iframe，定制化改后端配置下发 + postMessage 桥 | 宿主样式零污染、安全边界清晰；形态切换不如纯 DOM 灵活 |
| RCA 与帮助中心不造新子系统（ADR-04） | RCA 用现有引擎/服务内编排，帮助中心同进程读现有 KB 表 | 不增部署单元、不造数据模型、沿用治理与审计 |
| 渠道广度克制（ADR-05） | 只补邮件工单 + 企微加密模式 | 产品定位差异，非缺陷；不做无真实需求的渠道 |
| A-1 闸门与规则正交 | availability 独立闸门，在规则命中之后、`keywordHandoff` 之前判定，不塞进 `handoff_rules` | 「能不能转」与「要不要转」两件事，塞进规则表语义混乱 |
| A-1 配置载体改渠道级 | `agent_cs_channel.business_hours_json`（原方案写 workspace 加列） | `CsVisitorService` 已持有 channel，且渠道表已有 `handoff_rules`/`handoff_keywords` 同域配置，零跨模块依赖 |
| A-2 不造新情绪分析器 | 统一两套口径（优先消费 `CsTurnSignalService` 的 SPI 信号，无信号回退中文词表）+ 暴露趋势 | 情绪分析早就在跑（契约层 `SentimentAnalyzer` 已落 `CsConversation`），缺的是口径统一与呈现 |
| B4 不走工作流 `tool` 节点 | 服务内直调 `SqlQueryService` | `buildForWorkflow` 会把装饰器传 null、审批强制 `auto`，取数会绕过 `CsToolGuard`（无审计/无幂等/无额度），MCP 列表还写死空 |
| C1 wait 复用审批暂停机制 | 抛 `ApprovalPauseException(approvalId=null)` 暂停，新增 `resumeWaitRun` + `/signal` 唤醒 | 不动机器主体；并行分支禁止暂停类节点 |
| C3-1 加密路线修正 | 仿 RAG `KbSecretCipher`：AES-GCM + `ENC:` 前缀 TypeHandler，放横切层 `common-encrypt` | 原方案「启用 mybatis-encryptor + AES-GCM」实测不符：框架走 Hutool `SecureUtil.aes`（ECB）且存量明文解密会炸；TypeHandler 让 15+ 读取点零改动 |
| D4 从开关式改为默认开 + 白名单 | `mcpSsrfGuardEnabled=true` + `mcpSsrfAllowlist`（回环/RFC1918/ULA 默认放行，169.254 与 100.64 不放行），白名单为空则启动失败 | 内网/回环是 MCP 常见合法部署，一刀切会废掉存量；默认关等于没有守护 |
| 原生协议保留 OpenAI 兼容为默认 | 只加 provider 字段 + 6 参重载，线程化到 11 处调用点 | 避免为十余种 provider 各写一套编排；兼容层效果明显差时才补原生 |
| 版本选择「框架兼容优先于追新」 | 从框架 jar 内嵌 pom 反查同款版本；Anthropic 锁 2.75.0 | 3.x 是跨 major 破坏性变更（`MessageParam.builder()` 被删），构造级测试会假绿，只有 formatter 运行时探针能抓到 |
| 验收只认 surefire XML 实数 | 一律读报告，不认 EXIT=0 | 根 pom 默认跳过测试时 surefire 打 `Tests are skipped` 且 EXIT=0；PowerShell `2>&1 \| Out-File; $LASTEXITCODE` 取到的是 Out-File 的 0，曾因此漏掉 TS5076 与 COMPILATION ERROR |
| 文档订正不抹除历史 | 过时处加「已订正」+ 交叉引用，只有头部状态行直接改写 | 追溯价值：读者要能看到「当时为什么这么判断」以及哪一步推翻了它 |
