# ForgeAgent 语音呼叫中心方案（AICC）

> 状态：V0 / V0.5 / V1 / V2 **全部交付**（2026-11-09）· 适用版本 6.1.0；真实 AICC 接入（V0-real）待有服务后启动
> 本文为**唯一现行文档**（合并原评估稿、v1 与 v2 三个版本的结论）；客服域上下文见 [02-智能客服域](02-智能客服域.md) 第一部分，实施批次验证数字同步收录于其第六节批次历史表。

## 一、定位与决策基线

呼叫中心解决「电话渠道」：呼入 + 机器人自助 + 坐席接管。ForgeAgent 只做**事件适配与业务落地**，媒体面由云托管 AICC 承载（不自建 WebRTC / SIP 媒体网关）。

| # | 决策 | 取值 |
| --- | --- | --- |
| D1 | 通道口径 | B（控制面）+ C（媒体面）双通道——电话网进不来浏览器 WebSocket，SSE 只做控制面（来电/转写/弹屏/工单事件），媒体面走云托管 AICC |
| D2 | 媒体面路线 | 云托管起步（华为云 AICC PoC） |
| D3 | 解禁范围 | 解禁电话渠道 / IVR（IVR 用「机器人直接应答 + 意图分流」替代按键菜单树）；不自建媒体网关 |
| D4 | 云厂商 | 中立适配层 `CsVoiceGateway` + 华为云 AICC 唯一实现 `AiccGateway`，换供应商只换实现 |
| D5 | 首期范围 | 呼入 + 机器人自助 + 坐席接管 |
| D6 | 数据与合规 | 录音回落 `forge-common-oss`；留存天数可配、音频出域可配（默认不允许） |
| D7 | 坐席侧 | 用 AICC 自带工作台，ForgeAgent 只做弹屏与工单 |
| D8 | 规模 | 30 坐席 / 30 路并发 / 月 40 万分钟（80% 预警、100% 拒绝新呼入）；暂无 400/95 号码与 SIP 中继，留扩展接口 |
| D9 | 模块形态 | 独立 `forge-callcenter` + 公共契约层 `forge-callcenter-common`（取代 v1 的子包形态） |

## 二、模块形态与契约层

```
forge-admin（单 jar）
  ├── forge-callcenter           （语音域，com.forgeagent.callcenter）
  │     ├── forge-customer-service （复用 public Service 落业务）
  │     └── forge-callcenter-common
  ├── forge-customer-service     （文本客服域，S0~C4 已交付）
  └── forge-callcenter-common    （零业务依赖纯契约层，仅 JDK）
```

依赖严格单向：`callcenter → customerservice → callcenter-common`。公共层不依赖 Spring 上下文、MyBatis、Redis，可单独编译与单测。

**公共层内容**（`com.forgeagent.callcenter.common`）：
- 从 customerservice 搬入 4 类：`CsEventEnvelope`（统一事件信封）、`CsRealtimeTransport`（控制面通道接口，`pushBinary` 显式抛异常——媒体面走 `CsVoiceGateway`）、`CsPiiMasker`（号码与文本脱敏）、`CsChannelSignature`（签名 + 时间窗 + 常量时间比较）。
- 新增 4 类：`CsEventTypes`（**全部事件名唯一来源**：文本 12 + 语音 9）、`CsScene`（CONSOLE/CS/VOICE）、`CsChannelType`（含 VOICE_INBOUND）、`CsDefaults`（共享默认值与配置键名常量）。
- **不搬**：`SseRealtimeTransport`（依赖 RunEventBuffer，是实现不是契约）、`CsModuleProperties` 等文本域专属配置、所有 domain/mapper/service/controller。
- 配置粒度：公共层只放默认值常量，不搬 `@ConfigurationProperties` Bean（prefix `agent.customer-service` / `agent.callcenter` 各自保留，避免同 prefix 互相干扰）。

**callcenter 模块结构**：`config`（CallcenterProperties / 条件装配）、`gateway`（CsVoiceGateway / AiccGateway / CsVoiceEvent / VoiceProvider）、`service`（回调守卫、事件分发、8 态状态机、幂等、转写/录音入库、CDR 对账、坐席状态、业务绑定）、`domain`+`mapper`（4 表）、`controller`（`/chat-voice/**` 免登录回调 + `/agent/customerservice/calls/**` 坐席端）、`task`（录音留存清理）。

**跨域边界**：语音域表前缀 `agent_cc_*`，**不给** customerservice 的 `agent_cs_*` 表加列（独立模块相对子包形态的改进，跨模块改表消失）；业务表通过 `CallBusinessBinder` 调 public Service 写入。URL 不变：`/chat-voice/**`、`/agent/customerservice/calls/**`。

## 三、接口契约（AICC 回调）

`POST /chat-voice/{provider}/{code}`（免登录，`security.excludes` 放行，IP 限流沿用 `CsChannelGuard`）：

| 项 | 规范 |
| --- | --- |
| 请求体 | AICC 风格 `workNo` + `eventList[]`（`eventType` / `workNo` / `eventGenTime` 毫秒 / `content`，按产生顺序最新在最右），归一化为 `CsVoiceEvent` |
| 鉴权 | 坐席事件推送用 `Guid` + 可选 `service_token`；语音通知/挂机回调用共享密钥（≥16 字符）HMAC 签名；`CsVoiceCallbackGuard` 常量时间比较 + 时间窗 + nonce 去重 + callId 幂等 |
| **响应** | **必须返回厂商格式** `{"message":"success","retcode":"0"}`；失败 `retcode` 非 0 + 模糊 `message`、HTTP 200（避免 AICC 无限重试与渠道探测）；**不返回项目 `R<T>`** |
| 乱序与幂等 | 事件轨迹唯一键 `(media_provider, call_id)` / `(call_id, event_seq, event_type)`；重复事件直接返回成功不重复处理；CDR 迟到由 `CdrReconciler` 补写 |
| 失败 | 异常统一落死信事件 + 服务端日志，对外只回通用失败码 |

**V0-real 待核对项**（不阻塞，有服务后按官方文档核对）：`cec_07_0065` 正文（当时 404）、呼叫级报文字段与共享密钥签名算法、录音取回 URL 形态、租户 `AUTHMODE`。核对结果只改 `AiccGateway` 字段映射表，业务层零改动。

## 四、数据模型（`agent_cc_*`，SQL `agent_cc_c0.sql`）

| 表 | 要点 |
| --- | --- |
| `agent_cc_call` | 通话主记录：callId 幂等键、主被叫（**PII 脱敏后存储**）、8 态 status、通话/计费时长、挂机原因、`recording_oss_key`（只存对象键不存云侧 URL）、retain_until；唯一键 `(media_provider, call_id)` |
| `agent_cc_call_event` | 事件轨迹只追加：`(call_id, event_seq, event_type)` 唯一，乱序判定与幂等去重的数据基础 |
| `agent_cc_call_segment` | 实时转写分片：speaker（caller/bot/seat）、脱敏文本、时间轴、ASR 置信度——弹屏/质检/摘要的数据源 |
| `agent_cc_call_seat_state` | 电话坐席签入态：work_no、ready_state（OFFLINE/READY/PAUSE/TALKING/WRAP_UP） |
| `agent_cc_channel_config` | 语音回调渠道配置（与文本域 `agent_cs_channel` 双表同码并存，缺一不可） |
| `agent_cc_metric_daily` | 通话日指标 |

审计事件扩展：`RECORDING_ACCESS` / `RECORDING_EGRESS` / `RECORDING_PURGE` / `CALL_CDR_RECONCILE`。

## 五、状态机与工单映射

呼叫 8 态：`RINGING → ANSWERED → BOT_SERVING → WAITING_AGENT → AGENT_SERVING → HOLD → WRAP_UP → ENDED`，单调推进、乱序与迟到 CDR 不回退；异常事件落 `dead.*` 死信轨迹。

与工单七态**两表两套枚举、单向映射**：ring 建会话、transfer 建工单入 ACD 队列、坐席就绪触发自动分配、挂机按合法跃迁结案（RESOLVED 自动发 CSAT）；`HOLD` 不映射工单 `ON_HOLD`。

## 六、录音与合规链路（D6）

`call.record.ready` → 验签/幂等 → `audioEgressEnabled` 校验 → 拉取一次 → `OssClient.upload` → 只存对象键 → 坐席访问走 `presignGetUrl` 短期签名 + `RECORDING_ACCESS` 审计 → `CallRetentionTask` 到期 `delete` + `RECORDING_PURGE` 审计 → 会话擦除级联删通话/转写/录音。

两个可配项语义：
- `recording-retention-days`（默认 180）：录音对象与转写分片留存天数，独立于文本 `retentionDays`。
- `audio-egress-enabled`（默认 false）：控制**音频副本是否允许出域给第三方**（外部 ASR/质检/大模型/归档）。false 时只使用 AICC 内置 ASR/TTS，第三方质检只能拿转写文本；true 时每次出域写 `RECORDING_EGRESS` 审计。本地 OSS 存储不算出域。

存储可切换：`recording-store: local-fs`（开发，本地目录 + HMAC 签名下载，无真实 OSS 也可跑通）/ `oss`（生产，走 `sys_oss_config`），对象键规则一致、业务代码零改动。号码与转写统一走公共层 `CsPiiMasker` 脱敏。

## 七、配置项（`agent.callcenter.*`）

```yaml
agent:
  callcenter:
    enabled: false                        # 默认关；prod 下 AICC_MOCK / mock.enabled=true 拒绝启动
    provider: AICC                        # AICC / AICC_MOCK
    callback-tolerance-seconds: 300
    callback-secret: ${CS_AICC_CALLBACK_SECRET}   # ≥16 字符，不落库不硬编码
    recording-store: oss                  # local-fs（开发）/ oss（生产）
    recording-retention-days: 180
    audio-egress-enabled: false
    recording-presign-ttl-seconds: 300
    transcript-push-enabled: true
    handoff-on-low-confidence: true
    low-confidence-threshold: 0.60
    max-seats: 30                         # D8 规模门禁
    max-concurrent-calls: 30              # 80% 预警 / 100% 拒绝新呼入
    budget-monthly-minutes: 400000
    number-provider: noop                 # NoopNumberProvider，留扩展位
    trunk-provider: noop
    aicc:
      endpoint / tenant-id / app-key / auth-mode / skill-group-id / service-number   # 全走环境变量
```

prod 校验：`CallcenterProductionReadinessValidator` 对默认密钥、长度不足、AICC 参数缺失拒绝启动。

| 接口 | 默认实现 | 后续实现 |

| `NumberProvider`（allocate/release/describe） | `NoopNumberProvider` | 接 AICC 号码池 |

## 九、AICC Mock 契约（开发调试基线）

- 供应商标识 `AICC_MOCK`，仅 dev/test 生效；prod 下拒绝启动。
- 签名 HMAC-SHA256：待签串 `timestamp + "\n" + nonce + "\n" + rawBody`，Base64URL 放 `X-Cc-Signature`；dev 共享密钥见 fixture 目录。
- fixture（`forge-callcenter/src/test/resources/mock/aicc/`）：11 个事件报文 + `sequence.json`（签名与响应契约、事件映射、幂等键规则、状态机目标态表）+ 固定 WAV 录音字节 + 调试发送端与验证脚本（工作区 temp/）。**报文样例与字段映射的真源是 fixture 文件**，文档不重复。
- Mock 只作用于 `AiccGateway` 的 verify/parse/fetchRecording；业务层与真实供应商共用同一套代码——`provider=AICC_MOCK` 与 `AICC` 共用同一套业务断言。

## 十一、明确不做

1. 不自建 WebRTC / SIP 媒体网关，不引 WebFlux，不新增部署单元（单 jar 单库）。
2. 不自建号码资源池与 SIP 中继；本期不做号码分配策略。
3. 坐席排班、监控大屏、外呼不做（无真实需求）。
4. Mock 不用于生产（prod 校验拒绝启动）；Mock 只作用于适配层三方法，业务层不感知。

## 十二、决策与取舍记录

| 决策点 | 结论 | 依据 |
| --- | --- | --- |
| 为什么推翻「语音期切 WebSocket」（评估稿核心结论） | 电话入口是 PSTN → SIP 中继 → RTP 媒体网关，浏览器 WebSocket 接不进电话网；上行音频流、二进制 TTS、barge-in 都是 WS 才可行，SSE+HTTP 上行不可行 | 但媒体面最终由 AICC 承载后，连 WS 也不需要——控制面 SSE 已够 |
| 为什么保留中立适配层 | 华为云 AICC 接口事实多处待核对，`CsVoiceGateway` 字段映射表隔离，供应商差异不进业务代码 | 换供应商只换实现 |
| 为什么模块形态选 C（独立模块 + 公共契约层） | 文本域与语音域依赖同一份契约，事件类型与通道语义只有一处定义；`agent_cs_*` 表不再被语音模块加列 | 代价是动已交付代码（4 类搬移 + 11 处 import），用 V0.5 单独成期 + 端到端回归压住回归面 |
| 公共层零依赖纪律 | pom 只保留 test 依赖；CI 检查项：公共层出现业务依赖即失败 | 防层级倒挂 |
| V0.5 单独成期 | 把「动已交付代码」与「接新语音能力」分开验证，不绿不进 V1 | 回退点清晰 |
| 配置抽取粒度 | 只抽 `CsDefaults` 常量，不搬 @ConfigurationProperties Bean | 搬 Bean 会改已交付 prefix 与生产配置语义 |
| 响应格式 | 厂商格式 `{message,retcode}` + HTTP 200 | 项目 `R<T>` 会让 AICC 重试失控 |
| 表边界 | 语音域独立 `agent_cc_*`，不给 `agent_cs_*` 加列 | 跨模块改表是 v1 的缺陷，C 版消除 |
